# ADR 0002: shadcn/ui Component Library Setup with Pointer Cursor

- **Status**: Accepted
- **Date**: 2026-10-16
- **Deciders**: ianmaciel7

## Context
Following the baseline Next.js and Biome configuration in ADR 0001, we need an accessible, customizable, and high-performance component library. We want full ownership of the UI component source code without third-party runtime package lock-in, while maintaining standard interactive button cursor behavior.

## Decision
We initialize shadcn/ui using the official recommended defaults with pointer cursor:

```bash
pnpm dlx shadcn@latest init -d --pointer
```

Key architectural choices:
1. **Component Primitives (Base UI)**: Powered by the new `base-nova` preset using Base UI as recommended by shadcn for Next.js.
2. **Code Ownership (Copy-Paste Philosophy)**: Components live inside `src/components/ui/` rather than in an opaque `node_modules` package, enabling full customization.
3. **`--pointer` Flag**: Explicitly enables `cursor: pointer` for button primitives to preserve intuitive clickable user experience.
4. **CSS Variables & Tailwind v4**: Configured to work seamlessly with Tailwind CSS variables in `src/app/globals.css`.
5. **Integration with Biome**: Component files generated by shadcn conform to Biome formatting and linting rules.
6. **Starter Page Native Composition (`src/app/page.tsx`)**: The starter screen preserves the iconic Next.js starter layout hierarchy while utilizing native shadcn/ui components (`Button`, semantic tokens) and Next.js `Link`.
7. **Base UI Non-Button Element Composition (`nativeButton={false}`)**: When composing `<Button>` with non-button elements such as `<Link>` via the `render` prop (`render={<Link ... />}`), `nativeButton={false}` must be explicitly provided to comply with Base UI accessibility contracts and prevent runtime console warnings.
8. **Proportional Component Sizing**: Interactive CTA buttons in the starter view are configured to `h-11 sm:h-12 w-full sm:w-[160px] rounded-lg` to match the visual scale of the hero typography and adhere to the `--radius` design token, avoiding under-sized default button variants in wide layouts.

## Consequences
- **Positive**:
  - Full control over component code, styling, and accessibility attributes.
  - Consistent pointer cursor styling across all interactive button elements.
  - Zero heavy third-party UI runtime overhead.
  - Zero runtime warnings from Base UI button semantics when rendering links.
  - True visual adherence to shadcn design tokens and radius variables across the starter view.
- **Negative / Trade-offs**:
  - Component updates from upstream shadcn need to be pulled or maintained manually in the repository.
